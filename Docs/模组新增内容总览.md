> **对比基线**：原版《杀戮尖塔 2》0.111.0 ｜ **模组分支** `dev` ｜ **最新发布版本**：**0.9.0**（见 `UpdateDocs/0.9.0.md`）
> 本文描述 0.9.0 发布时的全量状态。0.9.0 相对 0.8.0 新增仙元体系、仙蛊唯一、父蛊→子卡强化等，见第 11 节。

## 1. 一句话总览

模组新增了**自定义角色「蛊真人」**，并围绕"蛊"搭起一条与原版卡牌体系**平行运转**的玩法链路：

> **蛊牌**（消耗元气、走专属四牌堆循环）→ **蛊转**（1–9 转品阶成长）→ **空窍**（战斗胜利修炼，六转入仙窍）→ **仙元**（仙窍阶段的第二货币）→ **合练 / 杀招**（篝火配方与战斗内组合技）→ **伴生牌**（蛊带出的普通牌，可挂专属强化槽）

配套提供专属 UI（蛊手牌第二层、元气转盘、蛊方大全图鉴）、专属美术与中英双语本地化。

### 与原版体系的对照

| 原版概念 | 模组的对应/扩展 |
| --- | --- |
| 能量 | 蛊牌改用**元气**（副资源），普通牌/伴生牌仍用能量（双轨并行） |
| 抽牌堆 / 弃牌堆 / 消耗堆 | 蛊牌**不进**原生抽弃循环，改走**蛊待命堆 → 蛊手牌 → 蛊冷却堆（→ 蛊封存区）** |
| 卡牌升级（Upgrade） | 蛊牌不可原生升级，改走篝火**「升炼」**提升**蛊转** |
| 附魔（`CardModel.Enchantment` 单槽） | 伴生牌新增**「强化槽」**（前置 MultiEnchantmentMod 的旁路额外附魔槽），原生附魔与强化共存 |
| 篝火休息点 | 新增**升炼**、**合练**两个独立选项（幂等注入，不替换原版选项） |
| 卡牌奖励 | 本角色的奖励池**只出真蛊牌**；伴生牌 / 杀招 / 仙元牌不可直接奖励获得 |
| 卡牌图鉴 | 新增**蛊方大全**（四页签只读图鉴，顶栏按钮入口） |
| 角色成长（无） | 新增**空窍**转数成长线：修为 → 转数 → 元气曲线 → 仙窍 → 仙元 → 仙蛊唯一 |

## 3. 新资源体系

### 3.1 元气（蛊牌专属战斗资源）

- RitsuLib 副资源 `yuan_qi`，**仅当前战斗内存在**，有独立的五层旋转表盘 UI（含亮/暗图层与前后粒子特效）。
- **按空窍转数成长的曲线**（战斗开始补满至当前转数上限，之后每回合回复）：

| 转数 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 元气上限 | 3 | 4 | 4 | 5 | 5 | 6 | 6 | 6 | 6 |
| 每回合回复 | 1 | 2 | 2 | 2 | 2 | 3 | 3 | 3 | 3 |

- 六转进入**仙窍**后封顶（上限 6 / 回复 3），续航改由仙元牌承担。
- 蛊牌卡面费用区由补丁改写为**元气数字 + 元气图标**（原版只认能量费用，会把蛊牌画成 0 费）。

### 3.2 仙元（仙窍阶段货币，0.9.0 起）

六转起引入的**第二种货币**，形态特殊——不是数值资源，而是**停在蛊手牌里的货币牌**：

| 仙元牌 | 发放转数 | 面额（催动单位） |
| --- | --- | --- |
| 青提仙元 | 六转 | 2 |
| 红枣仙元 | 七转 | 4 |
| 白荔仙元 | 八转 | 8 |
| 黄杏仙元 | 九转 | 16 |

- 每场战斗开始按当前转数发放一张（不占起手抽牌、不占蛊手牌 5 槽，固定悬停在蛊手牌最左端）。
- **催动附加消耗**：六转及以上的蛊牌每次催动，在照付元气之外**额外**消耗仙元单位——六/七/八/九转分别 **1 / 2 / 4 / 8** 点（指数翻倍）；仙元不足时无法催动（战斗提示「仙元不足，无法催动六转以上的蛊」）。
- **主动打出**：花 1 个单位把元气补满到当前上限。
- 单位耗尽后保留成不可打出的死牌直到战斗结束；余额写在 `SavedAttachedState` 上随战斗快照/联机同步。

### 3.3 起始遗物：空窍

| 项 | 内容 |
| --- | --- |
| 名称 | 空窍（Common，角色起始遗物） |
| 表面效果 | 战斗胜利获得修为，修为满提升转数；转数决定元气上限与回复（卡面实时显示 `{Rank}`/`{CurrentXp}`/`{RequiredXp}`） |
| 实际职责 | 整条蛊牌链路的**时机挂接点**：蛊牌使用登记/回收、回合元气补给、篝火选项注入、奖励清理、杀招推演发放、仙元扣费等全部挂在它的战斗钩子上 |

## 4. 新卡牌类别：蛊牌

`AbstractGuCard` / `IGuCard` 定义的**全新卡牌类别**，与普通卡牌的关键差异：

| 维度 | 蛊牌 | 原版普通卡牌 |
| --- | --- | --- |
| 费用 | **元气**（原生能量费恒 0） | 能量 |
| 所在牌堆 | 蛊牌四牌堆（不进抽弃循环） | 抽牌堆/手牌/弃牌堆 |
| 成长 | **蛊转 1–9 转**（升炼提升，奖励入手时赋阶） | 原生升级 |
| 可打出条件 | 位于蛊手牌（或出牌事务中的原生手牌）+ 元气足够 | 位于手牌 + 能量足够 |
| 战斗内随机生成 | 一律禁止 | 视卡牌而定 |
| 持久化 | 转数等写入 `SavedAttachedState`，跨存档 + 联机同步 | 原生存档字段 |

**蛊牌通用参数**（具体牌可覆盖）：最高 9 转；每周期催动 1 次；每次 1 元气；催动后冷却 2 回合（合练蛊 3 回合）。

### 4.1 蛊牌专属四牌堆（仅战斗内存在）

| 牌堆 | 编号 | 作用 | 容量 |
| --- | --- | --- | --- |
| **蛊手牌**（激活区） | `gu_active` | 可直接催动，作为普通手牌**后方的第二层**展示 | **5** |
| **蛊待命堆** | `gu_storage` | 已可用、等待补位的蛊 | 无限 |
| **蛊冷却堆** | `gu_recovery` | 次数耗尽后冷却 | 无限 |
| **蛊封存区** | `gu_sealed` | 被杀招封装的材料（不补位、不冷却、不可当推演材料） | — |

**循环**：待命堆 → 蛊手牌 →（次数耗尽）冷却堆 →（冷却到期）待命堆；每回合能量重置后先恢复到期蛊、再从待命堆按序补满蛊手牌。战斗开始时全部蛊牌收入待命堆，前 5 张在原生首抽后带入场动画进入蛊手牌。

### 4.2 蛊转（品阶）与赋阶

- **1–9 转**，数值随转数线性/倍率成长；奖励入手时按楼层**高斯抽样**赋初始转数（均值随楼层缓升、σ=2、固定随机流名，结果可复现）。
- 蛊牌不可原生升级；升转只能通过篝火**升炼**或**合练**继承材料转数。

## 5. 新玩法系统

### 5.1 篝火新选项一：升炼

- 休息点新增独立选项（与原版选项并存，各自幂等注入）：每次提供 **2 个升炼槽**，六转以下 1 槽、六转及以上 2 槽。
- 带**原版升级式绿色差异预览**（补丁接管 `IsUpgradable` / `UpgradeInternal` / 升级预览文案）。

### 5.2 篝火新选项二：合练

- 以蛊牌为材料的**无序配方合成**体系：配方声明在结果牌上（`[HeLianRecipe]`），材料必须是蛊牌且**至少两张**，只比对类型与数量（顺序无关），可要求材料**逐张达到最低转数**。
- 流程：选目标（只读预览）→ 选匹配材料 → 消耗材料产出结果蛊；**失败不消耗本次休息机会**。
- 结果转数 = 材料最高转数；合练结果蛊默认**不进卡牌奖励**。
- 注意：材料蛊带有的伴生牌会被**连带失去**。

### 5.3 杀招框架（战斗内组合技，池暂为空）

- 第二套配方体系 `[ShaZhaoRecipe]`（材料 ≥1 张即可，同样无序多重集 + 最低转数），**杀招刻意不是蛊牌**：走原生能量与手牌规则，不参与蛊牌循环。
- **杀招推演**系统牌：空窍**三转**起每场战斗开始发放（不占起手抽牌、可保留）；打出后选目标杀招 → 从蛊手牌/蛊待命堆选材料 → 支付材料元气均值的额外元气 → 材料封入**蛊封存区**、杀招入手且**首次打出免费**；杀招用尽后材料返还冷却堆并额外 +1 回合冷却。八转起每场可推演 2 次。取消/失败全额返还。
- ⚠️ **当前杀招池为空**（无任何具体杀招），推演牌按设计不会被发放；补一张带配方的杀招牌即可启用整条链路。旧版的右键主动解体已在 0.8.0 移除。

### 5.4 空窍 / 仙窍（角色成长线）

| 阶段 | 规则 |
| --- | --- |
| 凡窍（1–5 转） | 战斗胜利得修为：**普通 1 / 精英 3 / 首领 5**；各转突破需求 1/2/3/4/5；每场最多升一转，溢出保留 |
| 入仙窍（5→6 转） | 修为满 5 直接进入六转；此后每场胜利固定 1 点仙窍进度 |
| 仙窍（6–9 转） | 突破需求 2/2/3；九转为当前终点。六/七/八/九转突破时最大生命 **+2/+2/+3/+3**（断线幂等补发） |
| 联动 | 元气曲线封顶（第 3.1 节）、杀招推演解锁（三转）、仙元发放与催动附加消耗（六转起）、仙蛊唯一生效（六转起） |

### 5.5 仙蛊唯一（0.9.0 起）

- **六转及以上的蛊牌视为仙蛊；同名仙蛊全整局唯一**（扫描全部玩家的永久牌组，不只当前玩家）。
- 两条仲裁入口：① 升炼/合练把蛊升到六转及以上时先仲裁，已有同名仙蛊则不升转；② 任何卡牌进入永久牌组时再次仲裁，冲突时拒绝入牌或把落败的既有同名仙蛊**降回五转**。
- 优先级按「首次成仙楼层 → 玩家槽位 → 牌组位置 → 玩家 NetId」确定，各联机端并发处理也能收敛到同一胜者。

### 5.6 伴生牌体系

- 蛊牌可声明**永久伴生牌**（`ICompanionSourceGuCard` → `Companion` 单项，或覆盖 `CompanionDefinitions` 声明**多种不同伴生**；每项自带数量，缺省 1）：来源蛊进入永久牌组时自动配出、随存档/联机自动配平（`CompanionRelationshipService.ReconcileDeck`）。恒光仙蛊（恒光刃 + 恒光障）、光蛊（光耀 + 光界）、璇光蛊、皓月霓裳蛊、宝月光王蛊都用多伴生。
- 伴生牌是**完整普通卡牌**：占普通手牌与抽牌堆、耗能量、可原生升级与附魔；**永不进卡牌奖励**——玩家的普通牌来源由奖励蛊牌间接决定。
- 保护：伴生牌不可移除（删除/事件突变保护）；来源蛊作为合练材料被消耗时伴生连带失去；联机端有独立的战斗卡牌映射（`CompanionNetworkMap`）。
- 部分伴生牌的基础数值**跟随来源蛊转数**（恒光刃 / 恒光障 = 转数 + 2，璇光刃 / 璇光幕 = 转数 + 2），由 `AbstractGuangDaoCompanionCard.RefreshSourceRankValues` 在卡面构建与结算前刷新。

### 5.7 伴生强化槽（0.8.0 起；现已改用前置 MultiEnchantmentMod 的额外附魔槽）

- 原版 `CardModel.Enchantment` **只有一个附魔槽**。0.8.0 曾以自研复合载体 `CompanionEnhancementSlot` 占住该字段来模拟双槽；现已改为依赖前置 **MultiEnchantmentMod**（清单声明 `min_version`）：前置在原版主槽之外旁路维护**额外附魔槽**，因此**原版附魔照旧占主槽、强化进额外槽，两者天然共存**，不再需要「摘下主槽 → 塞进载体 → 再放回」的中转，原载体遗留的三条原版识别缺口（`ThievingHopper` / `CloneRestSiteOption` / `Claws`）也随之消失。
- 挂载统一走 `MultiEnchantmentApi.ForceEnchant`（单次调用内跳过 `CanEnchant => false` 否决权，强化因此仍不会从原版事件 / 遗物 / 篝火等来源获得）；叠层由 `CompanionEnhancementRegistration` 集中登记为 `MergeAmount`；卡面额外图标页签、附魔钩子分发、悬浮提示与存读档持久化全部由前置负责。图标走 `images/enchantments/<类名>.png` 自动解析，缺失时不覆盖引擎默认图标。
- 提供通用挂载 API：`Attach / Remove / ClearRegular`，以及「**催动蛊牌 → 给它的伴生牌挂强化**」的唯一入口 `AttachToCompanionOf`。
- ✅ 强化已扩展到 **19 种**（月华、玉皮甲强化，以及光道/月系的辉映、炫光幕强化、引光强化、炽照、返照、霓护、皓辉、宝霓、宝月光王·衣、汇光、借辉、璇照、月王辉强化、虹行、太照、恒照、回照强化）。父蛊只做声明（`ICompanionEnhancementSourceGuCard.BuildCompanionEnhancementGrants`），挂载仍统一走服务层。
- **数值与层数分离**：`CompanionEnhancementGrant` 除了层数，还可以带 **Magnitude**（按转数给的数值，例如「折光格挡额外 +X」的 X）与 **UsesPerCombat**（按转数给的每场次数，例如恒照 1/2/3 次），以及 **CompanionTypes** 把不同强化分流到一只蛊的不同伴生（宝月光王蛊）。层数只用于卡面显示。
- **生命周期与本场次数**：强化挂载作用域固定为 `UntilCombatEnds` —— 只活到本场战斗结束、**不镜像进牌组**，下一场战斗必须由父蛊重新催动授予。可用次数按「战斗卡实例 + 强化类型」分账（`CompanionEnhancementUses`），**真正触发时**扣减（计数点在 `OnPlay`，前置对该钩子的派发发生在子卡效果结算之后，故最后一次仍吃满加成），扣到 0 立即移除、卡面图标消失；同一场战斗内重新催动父蛊不会回满次数。
- **触发门控**：光道伴生强化覆盖 `RequiresRefractionTrigger => true` —— 只有子卡**真正折光**的那次出牌才消耗次数，打出但没折光不会白扣（由 `GuangDaoCardPlay` 在折光段结算时登记）。
- **层数 ≠ 次数**：层数是强度，次数是可用次数。叠层、存读档与联机表现尚需实机验证。
- 已知限制：次数账本是纯运行时状态（不写存档），**战斗中途存读档**会重建战斗卡、账本清空因而次数回满；若需要严格封死，应把账本改为随卡持久化。

### 5.8 奖励池规则

- 本角色的卡牌奖励**只出现真正的蛊牌**（过滤伴生/杀招/仙元/系统牌），且移除空奖励界面；新蛊牌在奖励 `Populate` 时抽取初始转数。

### 5.9 光道机制：折光 / 聚光（dev 起）

| 项 | 内容 |
| --- | --- |
| **折光** | 记录本回合**上一张主动打出的普通牌**类型（攻击 / 技能）。打出一张带光道标签的普通牌时，若上一张存在且类型不同，触发该牌自己的「折光段」。本回合第一张牌不触发，类型相同不触发；自动出牌完全绕过 |
| **桥接牌** | 不带光道标签的普通牌（玉皮甲）正常把自己的类型提交进历史，帮助下一张攻击牌折光，但**自己不触发、也不消费强制折光标记** |
| **聚光 X** | 「X 次折光重复机会」。数值型折光开始前检查，若聚光 > 0 则消耗 1 层，正常结算后再把**整段折光**额外结算 1 次；一次折光事件最多消耗 1 层 |
| **纯功能折光** | 折光段只有抽牌 / 回元气 / 获得聚光 / 强制折光 / 回收等功能时，既不消耗聚光也不会被重复 |
| **强制折光** | 标记式：`下一张光道牌`（任意类型）或 `下一张光道攻击牌`（非攻击牌会跳过而不消费标记）。自然折光与强制折光同时成立只产生一个真实折光事件 |
| **九转光蛊** | 催动使本回合所有拥有折光段的普通牌无条件折光；聚光仍逐次消耗 |

- 判定真值保存在隐藏的玩家级状态 `ZheGuangPower`（`DynamicVars`，随战斗快照/读档/联机同步；`IsVisibleInternal => false`），战斗开始时由起始遗物静默挂载。
- 卡牌只能通过统一入口 `GuangDaoSystem` / `GuangDaoCardPlay` 读取结果与执行折光段，不得自行推导上一张类型或重复消费聚光。
- 聚光层数是可见状态 `JuGuangPower`（`PowerStackType.Counter`）。
- 详细设计：`Docs/光道设计/GuZhenRenRebuild_光道与月系卡牌设计_聚光重复版.md` 与同目录 xlsx。
