## 1. 版本摘要

0.7.0 把「玩家能不能看懂自己的牌」这件事补齐：卡面文案按旧模组（`STS2_GuZhenRen`）的**文言式头部 + 一句话机制**重写（`三转 · 冷却二`），被删掉的细节全部下沉到**蛊方大全**的「详细说明」；同时新开「卡牌大全」页签，把蛊牌池、杀招池、辅助池里的每一张牌（含伴生牌与「杀招推演」系统牌）都收进图鉴，每张牌都有自己的详情页。

同时修掉两个真实缺陷：蛊牌在原版可打出判定里永远得到 `BlockedByCardLogic`（RitsuLib 为「额外手牌」在 `CanPlay` 期间临时改写 `CardModel.Pile`）、以及蛊牌费用区只显示原生能量 `0` 而看不到实际元气消耗。人物立绘与选择界面背景同步替换为旧模组美术。

蛊牌核心循环（三牌堆、蛊转、升炼、伴生牌）、合练体系、杀招框架与空窍数值曲线在本次**未改动行为**。

## 4. 核心玩法系统

### 4.1 两个描述面

卡牌文案从「一句话讲完」拆成两份，互不重复：

| 面 | 键 | 读者 | 内容 |
| --- | --- | --- | --- |
| 卡面 | `<CARD_KEY>.description` | 战斗中、卡池、奖励界面 | 头部 + 一句机制，越短越好 |
| 蛊方大全 | `<CARD_KEY>.detailDescription` | 图鉴详情页「详细说明」 | 最详细：机制、公式、冷却、配方、伴生联动、获取 |

- 蛊牌头部固定为 `[blue]{RankCN}[/blue]转 · [gold]合练[/gold] · [gold]冷却[/gold][blue]{RecoveryTurnsCN}[/blue]`（`合练` 只出现在合练结果蛊上），英文用 `Rank {Rank} · Fusion · Cooldown {RecoveryTurns}`。
- 配色规则：**动态数值蓝（`[blue]`）、机制关键字金（`[gold]`）**；数值不加空格，头部与正文之间用 JSON 转义 `\n` 换行。
- 卡面不再写「催动 N 次」（`MaxUses` 恒为 1，属噪音）、不写配方脚注、不写公式；这些全部下沉到 `.detailDescription`。
- `.detailDescription` **不注入任何占位符**（只有卡面走 `AddExtraArgsToDescription`），因此公式一律用文字写（`伤害 = 5 + 转数`），文案里不允许出现 `{}`。
- 键由卡牌自身 `Id.Entry` 推导：新增卡牌只要补文案就自动进图鉴，界面代码无需改动；缺文案时详情页整块隐藏该分区。

### 4.2 蛊方大全

- **入口**：顶栏按钮（`RecipeCompendiumTopBarButton`）挂在原生小地图按钮左侧，悬停提示走 `static_hover_tips`；按钮由界面每 0.25 秒对位一次，顶栏重建后自动重新挂载。仅在冒险进行中显示。
- **四个页签**：
  1. **蛊虫大全**：蛊牌池全部蛊牌，行内显示转数与获取方式；
  2. **卡牌大全**：`GuCardCatalog.AllModCards` 的全部卡牌，蛊牌行走"转数 + 获取方式"，其余行走"费用 · 稀有度 · 类型"；
  3. **合练配方**：`HeLianRecipeRegistry` 的配方，行内「结果 ← 材料」可点；
  4. **杀招配方**：`ShaZhaoRecipeRegistry` 的配方，池为空时给可行动的空状态说明。
- **详情页三型**：
  - 蛊牌：贴图 + 元信息行 + 卡面描述 + 详细说明 + 转数按钮（1～9）+ 获取方式 + 合练路径 + 杀招路径 + 伴生牌；
  - 杀招：独立视图（费用取原生能量、组方材料可点）；
  - 普通牌 / 伴生牌 / 系统牌：贴图 + 元信息 + 卡面描述 + 详细说明，蛊牌专属分区整块隐藏。
- **数据来源**：界面只读 `GuCompendiumModel`（卡池 + 两个配方注册表 + 获取方式推导），不持有任何可变状态；详情页用 `ToMutable()` 克隆规范实例，预览转数以 `persist: false` 写入，避免污染全局卡池实例。
- **挂载时序**：`RecipeCompendiumSystem` 用 `CallDeferred` 延迟一帧入树——模组初始化在 `OneTimeInitialization.ExecuteVeryEarly`，早于 `LocManager.Initialize` / `ModelDb.Init` / 图集加载器注册。
- **文案表**：图鉴整块文案放在**原版既有表** `card_library`（模组自创表名不会被 `LocManager` 登记），代码内置一份中文副本 `BuiltInChineseText` 供编辑器预览与缺键兜底。

### 4.3 蛊牌费用区显示元气

蛊牌的元气费用存放在 RitsuLib 的副资源费用表（`SecondaryCosts().Set(...)`），`CardModel.EnergyCost` 固定为 0，因此原版 `NCard.UpdateEnergyCostVisuals` 只会把 `0` 画在费用位置。`NCardGuEnergyCostPatch` 在原名方法之后重写费用数字（`IGuCard.YuanQiCost`）、图标与配色（`YuanQiCostIconTint` / `YuanQiCostTextColor`），给节点打 `GuZhenRenRubildYuanQiCostApplied` 标记，非蛊牌则还原原版外观。该补丁只改本地 `NCard` 节点，不读写成名战斗状态，也不影响联机同步数据。

### 4.4 蛊牌可打出判定

原版 `CardModel.CanPlay` 执行期间，RitsuLib 为让「额外手牌」复用基于手牌的打牌流程，会临时改写 `CardModel.Pile` 的取值（`ModExtraHandCanPlaySemanticPatch` + `ModExtraHandSemanticContext` + `ModExtraHandCardPileSemanticPatch`）。此时激活区的蛊牌读到的牌堆是**原生手牌**而不是激活区，于是「必须位于激活区」的判定必然失败，表现为元气充足也点不动蛊牌（原版给出 `UnplayableReason.BlockedByCardLogic`）。`GuCardRuntime.CanActivate` 因此改为**同时接受激活区与原生手牌**（原生手牌也是蛊牌出牌事务中的临时位置），储备区 / 恢复区 / 封存区 / 抽牌堆 / 弃牌堆 / 牌组一律仍不可打出。

### 4.5 元气图标解析链路

卡牌左上角用哪个图标由两条覆盖决定：卡片级 `IModCardAssetOverrides.CustomEnergyIconPath`（蛊牌指向 `YuanQiSystem.LargeIconPath`）与卡池级 `IModBigEnergyIconPool` / `IModTextEnergyIconPool`（本次补上）。缺了卡池这一层，`EnergyIconHelper.GetPath(EnergyColorName)` 会去找原版图集里不存在的 `energy_guzhenrenrubild.tres`，表现为图标缺失。图鉴在数据装载后主动打印一次实际解析结果，便于一眼定位是哪一层没生效。

### 4.6 获取方式推导

优先级：① 初始牌组——反射卡牌类上的 `[RegisterCharacterStarterCard]`，反射不到张数时退回 `GuAcquisitionOverrides` 的兜底表（当前登记玉皮蛊 1、月光蛊 2）；② 卡牌奖励——读 `GuCardRewardRules.CanAppear`；③ 合练专属——读 `HeLianRecipeRegistry`；④ 杀招路径——读 `ShaZhaoRecipeRegistry`；⑤ 伴生牌——读 `ICompanionSourceGuCard`。带伴生牌的蛊被当合练材料消耗时会连带失去伴生牌，获取方式区会额外给出这条警示。

### 4.7 人物美术

`images/characters/` 下立绘（`GuZhenRenRubild_character_idle.png`）、头像与其描边三张 PNG 替换为旧模组美术；角色选择背景场景删掉叠加的立绘/图标节点，只保留背景贴图。

## 5. 战斗时序

本版**未改动战斗流程**，只有两处与战斗相邻的改动，按时机列出全链路如下（★ 为本次改动）：

1. **BeforeCombatStart**（遗物）：重置本场杀招推演进度；`ShaZhaoBindingService.ClearStaleBindings` 清残留材料绑定。
2. **BeforeHandDraw**（遗物）：空窍 ≥3 转且杀招池非空时发放「杀招推演」（不占起手抽牌）。
3. **回合开始 / AfterEnergyReset**（遗物）：先恢复到期蛊牌，再按转数补元气。
4. ★ **原版可打出判定 / 自动打出判定**：`GuCardRuntime.CanActivate` 同时接受激活区与原生手牌（4.4），不再因 RitsuLib 的牌堆改写而误判。
5. **打出蛊牌**：支付元气（副资源费用表）→ 结算效果 → 仍有次数回激活区，次数耗尽进恢复区。
6. ★ **费用区渲染**（纯表现）：原版刷新费用显示之后，`NCardGuEnergyCostPatch` 为蛊牌改写费用数字/图标/配色（4.3）。
7. **打出「杀招推演」**：选目标 → 选材料 → 计费 → 封装进封存区 → 生成杀招（首次打出免费）；失败则返还费用并回手牌。
8. **右键杀招**：1 费主动解体，材料返还并额外 +1 回合冷却。
9. **战斗结束**（遗物）：清理该玩家的全部材料绑定。
10. **战斗外**：顶栏按钮打开**蛊方大全**（只读卡池与配方注册表，不触碰战斗状态、随机数与多人同步）。

## 9. 已知限制与后续方向

1. **未做游戏内端到端验证**：本版只完成编译级静态验证、本地化 JSON 校验、场景结构校验与 Godot 资源导出校验（见第 10 节）。优先回归项：蛊牌能否正常点动（4.4 修复）、费用区是否正确显示元气数字与图标（4.3）、四个页签与「详细说明」的渲染、顶栏按钮在顶栏重建后是否重新挂载、以及推演流程是否仍正常。
2. **页签行在窄分辨率下会溢出**：4 个页签（最小 170 px）+ 搜索框（最小 260 px）的最小宽度已接近 1600 宽窗口的内容区；本版把搜索框最小宽从 300 降到 260 以容纳第四个页签，但没有做自动折行或横向滚动。
3. **详细说明与转数选择器解耦**：它写的是公式（`伤害 = 9 + 转数 × 2`），切换转数只刷新卡面描述与元信息行；没有实现旧模组那种「按转数逐转展开」的文本。
4. **图鉴详情页不渲染原生卡面**：只插贴图 + 文本，因此看不到真实卡框、费用图标与关键词标签；卡片实际外观仍需在卡池/战斗中确认。
5. **数字风格不统一是为了分面**：卡面用中文数字（`三转 · 冷却二`），图鉴元信息行与转数按钮用阿拉伯数字（`3 转`）。这是刻意的两个面，未强行统一。
6. **`.detailDescription` 是模组自用键**：游戏本体不读它，只有 `GuCompendiumModel.TryGetDetailDescription` 读；缺失时分区整块隐藏（不报错，但等于缺内容）。新增卡牌时必须同时补这个键。
7. **图鉴文案存在两份真相**：`card_library.json` 与 `RecipeCompendiumOverlay.BuiltInChineseText` 必须人工保持键一致；新增页签/分区需要在 `.tscn` 节点、`BindSceneNodes` 绑定、两张本地化表三处同步。
8. **编辑器预览只显示内置中文示例**：在 Godot 里打开 `RecipeCompendium.tscn` 不会读取本地化表，也不加载真实卡池数据（示例条目与真实内容是两套）。
9. **蛊牌贴图仍复用模板卡图**（`GuZhenRenRubildStrike.png` / `GuZhenRenRubildDefend.png`）。图鉴直接读卡牌 `AssetProfile`，换专属蛊图时界面代码无需改动。
10. **0.6.0 第 9 节的限制在本版依然成立**：仙元分支、手牌容量豁免、联机确定性重解析、材料顺序快照、杀招标签与蛊屋等均未移植；杀招池仍为空池，`ShaZhaoRecipeRegistry.HasAnyRecipe` 为假时推演牌不会发放。本次未触碰杀招框架行为。
11. **图鉴是独立只读界面**：未与卡池悬停、卡牌奖励界面、篝火合练界面联动（例如从合练选项里直接跳图鉴），也没有搜索历史/收藏等扩展能力。
12. **`RecipeCompendiumOverlay` 体量偏大**（约 2200 行，隐含界面 + 数据装配 + 文案兜底三层）：后续若继续加页签，建议先把「列表装配」与「文案兜底」拆成独立文件，再考虑新增页签。
