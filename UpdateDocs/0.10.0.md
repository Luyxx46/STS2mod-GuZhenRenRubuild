## 1. 版本摘要

0.10.0 的主线是**第二条成体系的流派**：**光道与月系**。它建立在一套叫「**折光**」的出牌节奏上——记录本回合**上一张主动打出的普通牌**类型，当打出一张带光道标签的普通牌、且类型与上一张不同时，触发该牌自己的「折光段」（额外伤害 / 额外格挡 / 抽牌 / 回元气 / 回收牌等）。在此之上是**聚光**：一种**有限次数的折光重复资源**——当一次**数值型**折光开始时若聚光大于 0，则消耗 1 层，并在正常结算后把**整个折光段**再结算一遍；一次折光事件最多消耗 1 层，纯功能折光既不消耗也不重复。

围绕这套机制落地了一整条路线：17 只新蛊（8 只奖励池蛊 + 9 只合练结果蛊）+ 22 张新伴生牌 + 17 种新强化（与既有 2 种合计 19 种）+ 9 条「结果转数 = 材料最高转数 + 1」的新配方，并补上 45 张专属素材（43 张卡图 + 2 张状态图标）与 `powers` 本地化表。

第二条线是**原版适配裁决的整体收口**：《原版适配清单》审计出的 18 条 ⚠️/🔧 项（`D-01` ～ `D-18`）在本版**全部落定**，其中 7 条落成新的 Harmony 补丁（原版升级→升转、变形补赋转数、拒绝原生附魔、苦难限激活区、永久入组兜底赋阶、烟雾/昏眩提示、死亡清理），其余为零代码口径（手牌语义不对齐、激活区不开启回合结束规则、蛊牌维持可删等）。

第三条线是**减法**：删除旧模组遗产 4 张蛊（铁甲蛊 / 血煞蛊 / 月影蛊 / 玄铁蛊），月刃 / 玉皮甲两张伴生牌与月华强化在删除后按需求整体恢复，并把伴生数量从 1 改为 3。

## 4. 核心玩法系统

### 4.1 折光：判定对象与触发条件

折光的判定真值保存在**隐藏的玩家级状态** `ZheGuangPower`（`IsVisibleInternal => false`），所有会参与结算的字段都放在 `DynamicVars` 里，因此读档、克隆副本与多人快照天然共用同一份战斗真值，不需要额外持久化层。

| 项 | 规则 | 出处 |
| --- | --- | --- |
| 判定对象 | **普通牌**（`CardType.Attack / Skill / Power`）且**不是蛊牌** | `ZheGuangPower.BeforeCardPlayed` |
| 触发条件（自然） | 本回合**上一张主动打出的普通牌**存在，且类型与本牌**不同** | 同上 |
| 触发条件（强制） | 本牌带光道标签，且存在满足范围的强制折光标记 | 同上 |
| 历史提交 | 本牌**整段复播/连锁全部完成**后才提交类型（`AfterCardPlayed` + `IsLastInSeries`） | 同上 |
| 蛊牌 | **完全绕过**：既不触发折光，也不改动「上一张类型」历史（避免蛊手牌层的动作打断普通牌交替链） | 同上 |
| 自动出牌 | `CardPlay.IsAutoPlay` 完全绕过 | 同上 |
| 桥接牌 | 不带光道标签的普通牌（例：玉皮甲）正常提交类型，但**不触发折光、也不消费强制折光标记** | `GuangDaoTags` / `BeforeCardPlayed` |
| 回合开始 | `AfterEnergyReset` 清空「上一张类型」与本次判定；**不清**强制折光标记与累计序号 | `ZheGuangPower.AfterEnergyReset` |
| 累计序号 | 整场战斗累计的真实折光次数（`GetTotalRefractionSerial`），供未来的卡牌级资源使用 | `GuangDaoSystem` |

- 「带光道标签」在本模组里**等价于**「这张普通牌自带折光段」：标签是 RitsuLib 的归属标签（`[RegisterOwnedCardTag(nameof(GuangDao))]`），蛊牌不带该标签。
- 判定与消费是**两个动作**：`GetRefractionResult` 只读；只有**主动调用** `ResolveRefractionEffectAsync` 的折光效果牌才会消费聚光——只记录真实折光而没有折光段的牌（桥接牌）不会空耗聚光。

### 4.2 聚光：有限次数的「折光重复」

聚光层数是**可见状态** `JuGuangPower`（`PowerStackType.Counter`），语义是「X 次折光重复机会」：

1. 数值型折光开始前检查聚光；
2. 若聚光 > 0，消耗 1 层（`PowerCmd.ModifyAmount(-1)`）并把本次结算遍数置为 2；
3. 折光段先正常结算一遍（`passIndex = 0`），再**整段**额外结算一遍（`passIndex = 1`）。

| 项 | 规则 |
| --- | --- |
| 分类决定权 | 由**卡牌基础折光段**决定（`GuangDaoRefractionKind.Numeric` / `Functional`），临时强化不改变分类 |
| 数值型 | 带伤害 / 格挡数值 ⇒ 消耗 1 层并把**整段**（含强化附加值）再结算一遍 |
| 纯功能 | 只有抽牌 / 回元气 / 获得聚光 / 强制折光 / 回收等功能 ⇒ 既不消耗聚光，也不会被重复，恒 1 遍 |
| 消耗上限 | **一次折光事件最多消耗 1 层**：`CurrentEffectResolved` 标记保证同一次折光内重复调用不会再扣 |
| 获取时机 | 折光判定发生在折光段开始之前，因此本次折光过程中获得的新聚光只能用于之后的牌 |
| 布尔效果 | 强制折光等布尔状态只在 `passIndex = 0` 施加（重复那遍只兑现附加数值），多次赋予不叠加 |
| 强化附加值 | `GainJuGuangAsync` 只在第 0 遍附加 `ExtraJuGuangOnRefraction`（避免重复翻倍） |

### 4.4 光道强化契约

- 光道伴生强化实现 `IGuangDaoCompanionEnhancement`，提供折光段的附加值：`RefractionDamageBonus(passIndex)`、`RefractionBlockBonus`、`ExtraJuGuangOnRefraction`、`ForcesNextRefraction`、`RewardsRepeatedRefraction`、`RecoverCostReduction`（默认全 0 / false，按需覆写）。
- **附加值的语义是「折光真正触发时由强化提供」**，卡牌只读取、不自行推导；因此折光段被聚光重复时，附着其上的强化会**跟着一起再次结算**（设计明确接受的乘法关系）。
- `passIndex` 让强化能表达「只在重复那一遍加伤」（太照）这类效果。
- **触发门控**：光道强化覆盖 `RequiresRefractionTrigger => true`，只有子卡**真正折光**的那次出牌才消耗可用次数；`GuangDaoCardPlay` 在折光段结算时统一登记，打出但没折光不会白扣。
- **按转数授予**：`CompanionEnhancementGrant` 支持 `Magnitude`（按转数给数值，如「折光格挡额外 +X」的 X）、`UsesPerCombat`（按转数给每场次数，如恒照 1 / 2 / 3 次）与 `CompanionTypes`（把不同强化分流到一只蛊的不同伴生，如宝月光王蛊）。

### 4.5 多伴生与按转数数值

- 蛊牌可以声明**多种不同伴生**（覆盖 `CompanionDefinitions`），每项自带数量（缺省 1）；恒光仙蛊（恒光刃 + 恒光障）、光蛊（光耀 + 光界）、璇光蛊、皓月霓裳蛊、宝月光王蛊都用多伴生。
- 伴生牌的基础数值可**跟随来源蛊转数**（例：恒光刃 / 恒光障 = 转数 + 2），由 `AbstractGuangDaoCompanionCard.RefreshSourceRankValues` 在卡面构建与结算前刷新。
- 初始蛊的伴生数量由 1 改为 **3**：初始牌组「月光蛊 ×2 + 玉皮蛊 ×1」因此带出 月刃 ×6 + 玉皮甲 ×3，普通抽牌堆开局即 9 张伴生牌。

## 5. 战斗时序

★ 为本版新增或改动的环节。

1. **BeforeCombatStart**（遗物）：`ApertureSystem.HandleCombatStarting` 重置本场进度；清残留杀招材料绑定。
2. ★ **战斗开始**：静默挂载隐藏的折光真值 `ZheGuangPower`（幂等；重连/房间重建会重复调用，因此必须抢在任何一张牌被打出之前）。
3. **BeforeHandDraw**（遗物）：先发杀招推演牌（三转起、杀招池非空），再发仙元牌（六转起按转数）。
4. **回合开始 / AfterEnergyReset**（遗物 + `ZheGuangPower`）：恢复到期蛊牌、按转数补元气；清空「上一张普通牌类型」与本回合无条件折光标记（强制折光标记与累计序号保留）。
5. ★ **可打出判定**：蛊牌走 `GuCardRuntime.CanActivate`（激活区或原生手牌，六转起还要付得起仙元）；苦难阻断（烟雾 / 昏眩）时的气泡由 `GuAfflictionWarningPatch` 换成蛊语境说明。
6. **打出蛊牌**：`BeforeCardPlayed` → 迁入原生手牌 → 登记催动 → 父蛊给伴生挂强化 → 六转起扣仙元 → 原生结算 → 有余次回激活区，否则进恢复区。
7. ★ **普通牌出牌前（折光判定）**：`ZheGuangPower.BeforeCardPlayed` 先清本次判定，再按「上一张类型不同」或强制标记决定是否折光；蛊牌、自动出牌、非标准类型全部绕过。
8. ★ **折光段结算**：`GuangDaoCardPlay.ResolveRefractionSegmentAsync` → `GuangDaoSystem.ResolveRefractionEffectAsync`（数值型且聚光 > 0 则扣 1 层 → 结算遍数置 2）→ 逐遍执行折光段（`passIndex` 0 / 1），并登记「折光已触发」供强化的次数门控使用。
9. **打出子卡**：前置额外槽的 `OnPlay` 派发（在子卡效果结算之后）→ `AbstractCompanionEnhancement.OnPlay`（sealed）→ 触发判定 → 效果 → 扣次数 → 扣到 0 立即移除强化。
10. ★ **整段复播完成后**：`ZheGuangPower.AfterCardPlayed` 把本牌类型提交进历史（仅 `IsLastInSeries`）。
11. **卡牌进入永久牌组**：`Hook.ShouldAddToDeck` 后缀 → 仙蛊唯一仲裁 → `GuDeckEntryRankPatch` 给放行的牌兜底补抽初始转数（并回填克隆副本转数）。
12. **奖励生成**：`CardReward.Populate` 后缀 → 抽初始转数（已有同名仙蛊则上限压到五转）→ 成仙登记；候选滤空时由 `GuCardRewardPatch` 回退放行原版流程。
13. **升转（升炼 / 合练）**：先过唯一性仲裁再提交转数；合练结果转数 = 材料最高 + 1。
14. **玩家死亡**：原版清理五个原生堆后，`GuDeathCleanupPatch` 把激活 / 储备 / 恢复 / 封存四堆的蛊牌一并 `RemoveFromCombat`（封存材料经 `ShaZhaoBindingPatch` 正常解绑）。

## 9. 已知限制与后续方向

1. **未做游戏内端到端验证**：本版只完成编译级 + 资源导出级 + 打包级验证（见第 10 节）。未启动游戏、未做任何存读档与联机验证，本版**没有任何实机结论**。
2. **折光 / 聚光的数值全部是首轮设计值**：伤害、格挡、元气、冷却与触发次数均未实测；设计案的「实测重点」与「推荐调参顺序」（聚光生成量 → 强化触发次数 → 折光数值 → 基础数值 → 元气/冷却 → 伴生数量）见 `Docs/光道设计/GuZhenRenRebuild_光道与月系卡牌设计_聚光重复版.md`。
3. **强化会随折光重复一起重复**：这是设计刻意的乘法关系（月华、辉映、宝霓等价值随之上升），但也是强度风险最高的一点——聚光命中一张高倍率牌时，整段（含强化附加值）都会再跑一遍。
4. **聚光一次折光最多消耗 1 层**：因此「聚光 5」不是「同一张牌折 6 次」，而是「之后 5 次不同的数值型折光各重复一次」；玩家若想精准投放到高价值牌上，需要靠九转光蛊的无条件折光或强制折光标记。
5. **折光只认普通牌**：蛊牌与诅咒 / 状态等特殊类型既不触发也不提交类型历史；因此蛊手牌层的操作不会打断普通牌交替链（这是有意的隔离，但也意味着「蛊牌 + 伴生牌」的节奏完全由普通牌侧承担）。
6. **桥接牌不消费强制折光标记**：不带光道标签的普通牌（例：玉皮甲）只提交类型历史；如果玩家期望它「兑现」强制折光，会发现标记仍在。
7. **D-02 / D-03 的口径是「蛊牌维持可删」**：原版删除类事件（含 `SlipperyBridge` 的随机删）完全可以删掉蛊牌，且没有回补渠道；这是刻意选择（玩家可精简牌组）。若实机后被判定体验损失过大，需要新裁决在 `IsRemovable` 侧保护 `IGuCard`。
8. **原生附魔对蛊牌一律拒绝**（D-05 / D-06）：蛊牌不再计入附魔类事件的「可附魔数量」门槛；伴生牌与普通牌不受影响。
9. **蛊牌不能升级，只能升转**：`CurrentUpgradeLevel` 恒为 0（D-01 拦截），因此 `IsUpgraded` 恒 false，原版「降级已升级牌」（Reflections / WelcomeToWongos 等）永远不会选中蛊牌；事件升级界面的「升级后」预览文案不会显示转数变化（实际执行会 +1 转），属已知观感限制。
10. **变形补赋是「重新定阶」而非「迁移转数」**（D-04）：变形产出的蛊牌按新获得一只蛊随机定阶（均值随楼层缓慢提高），与原蛊转数无关；变形走 `AddInternal`，因此需要独立的补赋入口。
11. **遗留补强候选：战斗内神化可绕过仙蛊唯一性仲裁**。`GuXianGuRules.TryCommitGuRankIncrease` 对 `Pile != Deck` 的候选直接放行（`GuXianGuRules.cs:145`），战斗内打出神化（永久升级所有可升级牌）会把激活区的 5 转蛊升到 6 转而不经同名仲裁，可能产出第二张同名仙蛊。本版未处理，待裁决。
12. **同伴（伴生）牌卡图仍有缺口**：22 张新伴生中只有部分有专属卡图，其余复用 2 张模板图；聚光状态图标已入库，其余状态图标仍复用既有素材。补图只需把同名 PNG 放进对应目录（见第 7 节）。
13. **强化次数的账本是纯运行时状态**：`CompanionEnhancementUses` 用 `ConditionalWeakTable` 按战斗卡实例分账，**战斗中途存读档**会重建战斗卡、账本清空因而次数回满；若需要严格封死，应把账本改为随卡持久化。
14. **折光真值依赖前置的 `DynamicVars` 持久化**：读档 / 联机快照正确性由 `ZheGuangPower` 的 `DynamicVars` 承载，未做实机验证；重连与房间重建会重复调用 `EnsureZheGuangAsync`，靠幂等保证不重复挂载。
15. **杀招池仍为空**：杀招推演牌只在杀招池非空时发放，因此整条杀招链路在 0.10.0 仍**不会在正常游戏里被触发**；补一张带 `[ShaZhaoRecipe]` 的杀招牌即可启用。
16. **本版有两处「不入库」的隐私处理**：`UpdateDocs/0.6.0.md` ～ `0.9.0.md` 与 `Docs/原版适配清单_蛊手牌系统.md` 正文含本机磁盘绝对路径，已从版本库移除（本机副本保留）。因此仓库内的历史发版日志只剩 `0.1.0` ～ `0.5.0`，0.6.0 ～ 0.9.0 的正文只在 GitHub Release 与本机保存。
