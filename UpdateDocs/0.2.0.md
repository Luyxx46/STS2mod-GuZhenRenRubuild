## 1. 版本摘要

0.2.0 用**真实美术**替换了 0.1.0 的全部占位素材，并把旧模组的「空窍」从固定数值的一转遗物改造为 1～9 转的成长体系。蛊牌体系（三牌堆、蛊转、升炼、伴生牌）与奖励规则在本次**未改动**。

| 系统 | 状态 | 一句话说明 |
| --- | --- | --- |
| 人物美术 | ✅ 可用 | 人物模型、阴影、头像组、选择背景、地图标记全部替换为真实美术 |
| 元气转盘 | ✅ 可用 | 角色原生能量盘与元气（副资源）盘改为旧模组的五层旋转表盘 + 前后粒子光效 |
| 空窍（转数） | ✅ 可用 | 1～9 转，战斗胜利获得修为；五转满后进入仙窍，六转起每场 1 点进度 |
| 元气上限与恢复 | ✅ 可用 | 由固定「上限 5 / 每回合 +2」改为按转数：上限 3～9、回合恢复 1～4 |
| 最大生命奖励 | ✅ 可用 | 六至九转突破时依次 +2 / +2 / +3 / +3，带断线幂等补发 |
| 蛊牌体系 | ⚪ 未改动 | 三牌堆、蛊转、升炼、伴生牌沿用 0.1.0 |
| 灾劫 / 仙元 / 杀招 / 合炼 | ❌ 未移植 | 旧模组的这些独立玩法模块未纳入本版本 |

## 4. 核心玩法系统

### 4.1 空窍转数

| 项 | 值 |
| --- | --- |
| 转数范围 | 1 ～ 9（九转为当前实现上限） |
| 仙窍阶段 | 六转起（`ImmortalRank = 6`） |
| 突破所需修为 | 1 转 1、2 转 2、3 转 3、4 转 4、5 转 5、6 转 2、7 转 2、8 转 3、9 转 0（终点） |
| 胜利修为 | 首领 5、精英 3、普通 1；六转起固定每场 1 点 |
| 单场上限 | 一场战斗最多提升一个转数，溢出修为保留到下一转 |
| 五转→六转 | 五转修为满后直接进入六转；仙窍阶段之间的突破从 0 点进度重新开始 |
| 最大生命奖励 | 六转 +2、七转 +2、八转 +3、九转 +3 |
| 持久化 | RitsuLib Run Saved Data，按玩家保存并随运行快照同步 |

- 胜利回调可能因断线重连或房间重建而重放：以运行层数（`VictoryXpAppliedFloor`）去重，并把「层数标记 + 修为变更」放在同一次 `Modify` 中提交。
- 最大生命奖励分两步提交：先记录「正在结算的转数 + 结算前最大生命」，执行 `CreatureCmd.GainMaxHp` 后再推进进度；进程在两步之间中断时会按目标上限补齐差额，不会重复获得。

### 4.2 元气（副资源）

| 项 | 0.1.0 | 0.2.0 |
| --- | --- | --- |
| 基础上限 | 固定 5 | 由空窍转数改写：3、4、4、5、5、7、7、8、9 |
| 硬上限 | 5 | 9（九转容量，钩子缺席时的兜底） |
| 首回合 | 补满 5 | 补满至当前转数上限 |
| 每回合恢复 | 固定 +2 | 按上限推导：1、2、2、2、2、3、3、4、4 |
| 下限 / 初始值 | 0 / 0 | 不变 |
| 回合开始自动恢复 | 无（由遗物显式管理） | 不变 |
| 持久化范围 | 仅当前战斗 | 不变 |

元气上限通过 `ISecondaryResourceHookListener.ModifyMaxSecondaryResource` 按转数返回；恢复逻辑仍写在起始遗物的 `AfterEnergyReset` 中（与 0.1.0 相同的挂接点）。

### 4.3 元气转盘显示

- 表盘为 128×128，五层贴图；`layer2`/`layer3`/`layer4`/`layer5` 以 45 / −45 / 22.5 / −90 度每秒旋转。
- 元气为 0 时切换为暗色图层、降低旋转速度（×0.25 或 5 度/秒）并停止粒子。
- 元气增加时重放前后粒子并播放回弹动画（1.0 → 1.08 → 1.0）。
- 文案颜色：有元气用米色、耗尽用红色；描边随之切换。

## 5. 战斗时序（0.2.0 相对于 0.1.0 的变化）

1. 战斗开始：不变（元气初始 0，由遗物在原生能量重置后发放）。
2. 原生能量重置后（`AfterEnergyReset`）：**先**恢复到期蛊牌（不变），**再**按当前转数补充元气——第 1 回合补满至转数上限，之后每回合按转数恢复，均不超过当前上限。
3. 蛊牌出牌与归位：完全不变（`BeforeCardPlayed` / `AfterCardPlayed`）。
4. 战斗胜利（`AfterCombatVictory`，**本次新增**）：先按房间难度发放修为并提交转数变化，再幂等补发六转起的最大生命奖励，最后刷新遗物图标与描述数值。

## 9. 已知限制与后续方向

1. **未做游戏内端到端验证**：本版本只完成编译级与资源/场景完整性验证（见第 10 节）。转盘旋转与粒子、人物模型站位、空窍升转与最大生命补发都需实机回归。
2. **灾劫 / 仙元 / 杀招 / 合炼未移植**：旧模组的这些独立玩法模块未纳入。因此六转起的「仙元牌加入手牌」等效果在本版本不存在，与旧模组的六转体验不完全等价。
3. **元气上限钩子的依赖**：元气上限依赖空窍遗物作为次级资源钩子监听者；若遗物缺失，上限会退回 `baseMaxAmount = 5`。
4. **最大生命奖励不可回退**：九转封顶后再无奖励；已发放的生命不会因为读档回退而收回。
5. **编辑器测试按键**：转盘脚本保留了 Q/E/Space/R 测试键，但默认关闭（`EnableKeyboardTest = false`）；如需在编辑器里预览，需在场景中手动打开。
6. **美术仍未完全去占位**：卡图仍复用模板图（玉皮蛊复用防御、月光蛊与月刃复用打击），角色与先古对话文案仍是模板文本——本次只移植了人物与转盘美术。
